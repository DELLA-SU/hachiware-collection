# 치이카와 가챠

파스텔 러브레터 콜라주 스타일로 치이카와 세계의 캐릭터 사진을 모으는 웹사이트입니다.

- 사진 뽑기, 번호·날짜·캐릭터 검색, 별표, 삭제 및 바로 복원
- 사진마다 메모와 드로잉, 확대·이동, 출처 링크
- 치이카와 노래 TV, 딸기 도트 캡슐이 열리는 인트로
- 원본 영상에서 편집한 우사기 목소리 14개를 중복 없이 섞어 재생
- 동작별 짧은 효과음과 음소거
- 배너와 수집 현황 디자인 비교 페이지 5종

공개판의 기록은 **방문자의 브라우저 IndexedDB**에 저장됩니다. 서버에 개인 메모나 드로잉을 전송하지 않습니다. 다른 기기와 자동 동기화되지 않으며 브라우저 데이터 삭제 시 기록도 사라집니다. 기록 내보내기는 사진 목록, 별표, 메모, 드로잉을 JSON으로 저장합니다.

사진 뽑기는 굿즈를 제외한 캐릭터 일러스트 목록 중 아직 모으지 않은 사진을 선택합니다. 전부 모으면 기존 사진을 다시 보여주고 중복 카드를 생성하지 않습니다. 공개판은 실시간 Pinterest 검색을 수행하지 않습니다.

방문 통계는 쿠키 없는 Umami Cloud Hobby와 선택 동의를 받은 Google Analytics 4로 집계합니다. 메인 도감·자격증·파자마 페이지의 조회와 고정된 기능 사용 이벤트만 전송하며, URL의 사진 식별자·검색어·메모·드로잉은 전송하지 않습니다. Umami는 설정에서 끌 수 있고 과거의 명시적 거부와 브라우저의 Do Not Track 설정을 존중합니다.

GA4(`G-YXDXZV7X3Y`)는 작은 동의 안내의 ‘동의’를 누른 경우에만 태그를 불러오는 기본 동의 모드입니다. 동의 전 행동을 나중에 재전송하지 않으며, 거절·철회 시 이후 전송을 차단하고 이 프로젝트 경로의 `hachiware_ga` 분석 쿠키만 지웁니다. 광고 저장·개인화·Google Signals는 끄고, 페이지 주소는 공개 UTM만 남기며 출처는 도메인까지만 전송합니다. 선택은 `hachiware-google-analytics-consent`에 저장하고, 기존 `hachiware-analytics-consent` 선택도 존중합니다. 페이지 아래 ‘Google 통계 설정’과 도감 설정에서 선택을 바꿀 수 있습니다. GA4 거절은 별도 Umami 설정을 바꾸지 않으며, 두 서비스의 방문자 수를 더하면 중복됩니다. GA4 향상된 측정은 관리 화면에서 꺼진 상태를 유지합니다. 개발 호스트에서는 두 서비스 모두 전송하지 않습니다. 이전 GA4 데이터는 유지됩니다.

파자마의 `pajama_dance_start`는 사용자가 재생을 눌러 영상이 시작됐을 때(반복 재생 제외), `pajama_photo_add`는 사진 적용에 성공했을 때 기록합니다. 자격증의 `certificate_select`는 직접 양식을 골랐을 때, `certificate_photo_add`는 사진 적용에 성공했을 때, `certificate_download`는 PNG 생성 후 다운로드를 실행했을 때 기록합니다. 파일 이름·사진·저장할 이름·선택한 자격증 정보는 보내지 않으며 다운로드 이벤트는 운영체제의 저장 완료를 보장하지 않습니다.

## 실행 및 배포

Node.js 22 이상에서 `npm install`, `npm run dev`로 실행합니다. `npm run build`는 GitHub Pages에 올릴 `docs/`를 생성합니다.

GitHub Pages 설정: `main` 브랜치의 `/docs` 폴더. 경로는 `/hachiware-collection/`입니다. 이미지, 음성, 스크립트는 해당 경로에 맞춰 구성되어 있습니다. `docs/.nojekyll`을 유지하세요.

- `banner-letter-preview.html`: 추가 배너 시안 5종
- `usagi-voices-preview.html`: 편집한 우사기 목소리 재생

개인 메모·드로잉 데이터, 로컬 서버 DB, macOS 실행 파일, 인증 정보는 저장소에 포함하지 않습니다. 캐릭터와 원본 사진·영상·음성의 권리는 해당 원저작자에게 있으며, 사진별 출처 링크를 제공합니다.

## 캐릭터 수집 키워드

`lib/collection-keywords.json`의 52개 캐릭터·그룹에 한국어 이름, 일본어 이름과 별명을 정의합니다. 사이트 검색과 공식 마켓 사진 후보 수집기가 같은 목록을 사용합니다. 이름은 공식 애니메이션 캐릭터 페이지와 치이카와 INDEX의 등장인물 목록을 참고했습니다.

- https://www.anime-chiikawa.jp/chara.html
- https://chiikawa.geo.jp/character/characterlist/

`python3 scripts/refresh-photo-candidates.py --pages 8 --output photo-candidates.json`으로 공식 마켓의 새 후보를 수집합니다. 후보는 사진과 캐릭터, 중복 여부를 검토한 뒤 catalog에 추가합니다. 이 명령은 공개 카탈로그나 개인 기록을 자동으로 덮어쓰지 않습니다. 검색어 추가가 무제한 사진 공급을 보장하지는 않습니다.

사진이 많은 캐릭터가 독점하지 않도록 캐릭터를 먼저 고른 뒤 해당 캐릭터의 새 사진을 고릅니다. 다른 캐릭터의 새 사진이 남아 있으면 직전과 같은 캐릭터를 피합니다. 사진 목록 소진 후에는 기존 사진을 다시 보여줍니다.

## 바탕화면 사진 전달

바탕화면 앱을 한 번 클릭하면 사진 창만 표시합니다. 사진 창의 ‘웹사이트 바로가기’를 누를 때 같은 사진 ID를 URL fragment로 기본 브라우저에 전달합니다. 브라우저는 카탈로그의 ID만 받아 IndexedDB에 저장하며, 이미 모은 사진은 중복 생성하지 않고 최근 만난 시각만 갱신합니다. 처음 모은 날짜, 별표, 메모와 드로잉은 유지합니다. 같은 브라우저의 다른 열린 도감 탭도 기록 변경을 감지합니다.

새 뽑기는 하치와레·치이카와·우사기·주인공 단체 그림 5회 후 서브캐릭터 1회로 진행합니다. 스티커·마그넷을 포함한 모든 상품 이미지는 새 뽑기에서 제외하며 원화·일러스트·애니메이션 자료만 사용합니다. 굿즈 자료는 과거 기록 복원을 위해 카탈로그에 남겨둡니다. 해당 종류의 새 그림을 다 모으면 같은 종류의 기존 그림을 다시 보여주며 중복 카드는 만들지 않습니다.
